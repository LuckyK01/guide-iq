# Contributing

## Branching

Create a short-lived branch for each change:

```text
feature/<short-description>
fix/<short-description>
docs/<short-description>
```

## Commit Messages

Use clear, focused messages, for example:

```text
feat: add document classification endpoint
fix: validate empty upload requests
docs: update local setup steps
```

## Pull Requests

- Keep changes focused and reviewable.
- Explain what changed and why.
- Include testing evidence.
- Update documentation with behavior changes.
- Do not include secrets or sensitive data.
- Obtain at least one teammate review where practical.

## Definition of Done

- [ ] Code runs locally.
- [ ] Tests pass.
- [ ] Error cases are handled.
- [ ] Documentation is updated.
- [ ] Dependencies are documented.
- [ ] Security and data-handling requirements are considered.
